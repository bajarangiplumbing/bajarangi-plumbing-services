{% comment %} HONEYPOT. LeadForm declares a `website` field and rejects any submission that fills it, but the field was never rendered in any template - so a bot posting directly simply omitted it and passed the check. It was an anti-spam control that existed only in the backend's imagination. aria-hidden and tabindex="-1" keep it away from screen readers and from the tab order, so it traps scripts without ever reaching a real user. autocomplete="off" stops a browser helpfully filling it in, which would otherwise reject a genuine customer as spam. {% endcomment %}
{% comment %} CONSENT - rewritten for DPDP Act 2023 s.6(1), which requires consent to be free, specific, informed and unambiguous, given by a clear affirmative action and limited to the stated purpose. The previous wording was "I agree to be contacted on this number about my request", which named no data, no purpose beyond "contact", and no recipient. It could not be described as informed, and it was materially incomplete in one specific way: it did not mention that submitting this form sends the details to a server and on to Meta via the WhatsApp Cloud API. The privacy page at the time actively denied that happened. The checkbox stays unchecked by default and the form will not submit without it, which is the "clear affirmative action" limb. consent_notice_version is submitted alongside so the server can record WHICH wording was agreed to. Without it, proving informed consent years later is impossible - the text would have changed and no record of the old one would exist. {% endcomment %}
